## Validation evidence

- `pytest -q`: **96 passed, 1 skipped, 1 warning** after correcting the migration head assertion to `0015_authorization_evidence_fingerprint`. The ordinary local run skipped PostgreSQL because no test URL was configured. A second full run against an isolated PostgreSQL 16 container completed **97 passed** with the PostgreSQL multiprocess case enabled. The warning is an existing Starlette/httpx TestClient deprecation.
- `python tests/e2e_browser_workflow.py`: **passed** against loopback-only fixtures; the reviewer step checks the authorization evidence fingerprint label.
- Targeted new-feature tests previously passed: APK parser text/binary manifest and unsafe archive cases, KMS mock encryption/purpose/fail-closed behavior, egress CIDR enforcement, authorization PDF fingerprint/discard and parser integration.
- `ruff check src tests apk_parser migrations`: **passed** after lint fixes. `python -m compileall -q src apk_parser migrations`: **passed**.
- `npm run build` in `dashboard/`: **passed**. `docker compose config -q` and `docker compose build --check`: **passed**. `docker compose build`: **passed** for API, dashboard and APK parser images. Images were built but containers were not started.
- Disposable PostgreSQL 16: fresh `alembic upgrade head` and `alembic check` passed at `0015`; an existing database at `0008` with `alembic_version.version_num` forced back to `VARCHAR(32)` upgraded to head after the env bootstrap widened it. The PostgreSQL test-enabled full suite reported **97 passed, 1 warning**; the 8 spawned processes produced exactly one reservation and seven blocked outcomes. A PostgreSQL 16 `pg_dump`/`pg_restore` into a second database restored revision `0015`, 17 public tables, and passed `alembic check`. The host's PostgreSQL 18 client could not restore its own dump to PostgreSQL 16 due `transaction_timeout`, so CI now runs dump/restore with the matching `postgres:16` tools image.
- Fresh SQLite migration to `0015` and `alembic check`: **passed**. Configured `apisentinel.db` was backed up before upgrading from `0014` to `0015`; a head backup restored to a new temporary path. Configured DB, backup and restored DB each report `PRAGMA integrity_check=ok`, revision `0015_authorization_evidence_fingerprint`, one analyst and zero clients; `alembic check` reports no drift on both configured and restored DBs. No existing records were changed by the migration.
- No public/third-party target was contacted. A disposable PostgreSQL 16 test container was started for the isolated migration/stress/restore drill and then removed. No application container was started, and no commit, push, or deployment was performed.

## Overall conclusion

Phase 1 remains **PARTIAL**. The previously missing APK parser, KMS envelope provider, runner CIDR policy, authorization document fingerprint, and PostgreSQL CI stress/recovery workflow now have implementations. External validation remains for live AWS KMS, host/VPC egress rules, hosted CI, and independent-host failure behavior. PostgreSQL migrations, multiprocess contention and dump/restore were validated locally against an isolated disposable PostgreSQL 16 container. APISentinel is not a comprehensive scanner or production-ready service.
