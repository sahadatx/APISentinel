# Coverage model

Coverage exposes separate measures for endpoint inventory review, HTTP transport, registered security checks, and analyst review of check-generated candidates. Retest provenance and state are recorded per retest but are not currently summarized as a percentage.

- **Endpoint inventory:** current imported endpoints, those in a reviewed state (`APPROVED` or `REJECTED`), and those approved for execution. Superseded endpoints are excluded.
- **HTTP transport:** denominator is current approved endpoints. The newest endpoint-linked HTTP request determines that endpoint's current transport state. `COMPLETED` means transport completed only; it is not a security verdict. The page shows that latest state beside historical check outcomes.
- **Registered security checks:** denominator is each current approved endpoint × each server-enabled registered check supporting its method and required transport scheme. For example, HSTS is planned only when the server-derived target for the endpoint is HTTPS. Legacy runs and transport-only TestRuns have no check ID and do not count. The latest recorded check outcome per endpoint/check is shown. A later queue attempt with `NOT_RUN` (for example, a cancelled attempt) does not erase an earlier actual outcome; it is shown separately as the latest attempt. Only `NO_ISSUE_OBSERVED` or `CANDIDATE_FOUND` increase evaluated coverage. Blocked, skipped, errored, inconclusive, and not-run outcomes do not increase completion. A check's coverage means that it produced an interpretable observation, not that a vulnerability was found or absent.
- **Finding review:** check-generated candidates are counted by assessment. A candidate is counted as triaged once an analyst moves it out of its initial `Candidate` state. This records analyst triage, not finding confirmation.
- **Retest:** each retest is an evidence/audit record, not an inventory or security-test coverage unit. A linked retest records its assessment, endpoint, TestRun, registered check/version, and endpoint-definition hash. Only a completed applicable registered check with `NO_ISSUE_OBSERVED` can produce the automated no-issue retest outcome; transport-only, blocked, skipped, error, inconclusive, stale-definition, and legacy unlinked retests do not count as successful retest coverage. Manual resolution is separately labeled `MANUALLY_RESOLVED` and relies on the authenticated analyst's notes/evidence.

Coverage responses link each endpoint/check cell to its originating TestRun and related finding IDs where present. Discovery, Testing, and Findings pages use the same selected assessment and persisted records. All resource queries remain assessment-scoped. Completion values describe recorded workflow activity and do not prove security, vulnerability absence, or confirmation of a finding.
