## Repeatable PostgreSQL recovery drill

The hosted CI workflow executes migrations on disposable PostgreSQL 16 and checks a clean migrated database plus a backup source containing a synthetic audit event. It uses the matching PostgreSQL 16 client image to dump and restore, then compares the restored Alembic revision and audit row count. Keep CI credentials fixture-only.

For an operator drill, use an isolated PostgreSQL instance and a synthetic marker record, never the live production database. Match client and server major versions. Retain the dump only in an approved encrypted location, restore into a new empty database, compare migration revision and selected non-secret record counts, run `alembic check`, verify application readiness and KMS decryption using an approved test credential, then delete the disposable instance and drill artifacts according to policy.

## Release decision

Local PostgreSQL restore evidence does not satisfy production recovery acceptance. Production readiness remains blocked until a hosted CI run is reviewed; the organization's audit retention schedule is approved; KMS/IAM and secret injection are verified; production TLS/ingress and host/VPC egress are inspected; and a deployment-specific restore acceptance is recorded.
