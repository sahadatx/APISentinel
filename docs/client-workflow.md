# Client workflow

Before an engagement, obtain written authorization, exact hosts and paths, excluded operations, request limits, testing windows, test identities, data-handling agreement, deliverables and deadlines. Enter a testing-window start and end together as timezone-aware timestamps; execution is allowed from the start through, but not including, the end. Keep the engagement in Draft until its scope is reviewed. Create the assessment and configure its target scope, then record the authorizing party, reference, validity period and permitted methods. A second explicit review action is required before the record becomes active. A sole active client member can use the audited self-review path; otherwise assign a different reviewer. Legacy Boolean/reference fields do not authorize execution. APISentinel records an operator attestation but does not verify legal authenticity; verify the source authorization outside the application.

Import documentation to inventory endpoints. Record findings only after analyst validation, redact evidence, review coverage, generate a report version, and record retest outcomes only with new evidence. Deliver through the agreed channel outside this local application; no marketplace or client messaging integration exists yet.
