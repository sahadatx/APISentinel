# Architecture

The backend is a synchronous FastAPI application over SQLAlchemy 2 and Alembic migrations. Analyst-owned client records contain assessments; assessments own authorization records, endpoint inventory, TestRuns, findings, reports and retest history. Canonical execution and lifecycle events are stored in `ExecutionAuditEvent`. SQLite is the local default; a relational database URL can be configured through `APISENTINEL_DATABASE_URL`.

The React + TypeScript + Vite dashboard calls the `/api/v1` API. `VITE_API_URL` sets the API origin for a built frontend. Assessments declare `WEB_API`, `ANDROID_API`, or `BOTH`; Android applications can be uploaded to a separate, resource-limited APK manifest parser container attached only to an internal Docker network. APK bytes are parsed without extraction, execution, or persistence; only sanitized manifest metadata and the APK SHA-256 are stored. Device telemetry and verified app/traffic provenance are not implemented. Web inventory accepts OpenAPI JSON, Postman v2.1, a structured Burp HTTP-history JSON subset, Browser HAR and Android traffic captures. GraphQL introspection JSON is stored separately as sanitized schema metadata; it is never converted into executable endpoint records. HTTP endpoint imports use the existing approval boundary. Client access uses owner-managed `viewer`, `analyst`, and `reviewer` memberships; it does not provide global administration. See [the security model](security-model.md) for scope, runner, test registry, and deployment limits. This local workspace is not client-ready.
